# DungeonSim Roadmaps

Roadmaps describe planned development direction and vertical-slice milestones. They are intentionally less detailed than implementation tickets and may evolve as completed work changes the design.

## Active Roadmaps

- [Core Gameplay Loop](Core-Gameplay-Loop.md) — closes the build, expedition, reward, progression, and risk/reward loop through planned tickets t002–t020.

## Planning Rules

- Roadmaps group work by vertical slice rather than treating ticket numbers as the design structure.
- Ticket IDs are stable and are never renumbered or reused.
- Planned roadmap items become detailed files in `docs/TODO/` when they are close enough to implementation to specify accurately.
- Keep roughly the next 2–4 tickets elaborated; avoid over-specifying distant work.
- Design documents describe enduring system behavior. Roadmaps describe sequencing. Tickets describe bounded implementation work.

## Ticket Statuses

Use these statuses consistently:

- Planned
- Ready
- In Progress
- Awaiting Unity Validation
- Complete
- Blocked
- Cancelled
